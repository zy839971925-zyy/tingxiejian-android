# 源码审查记录 — 2026-09-28

> [!NOTE]
> 这是 **v1.0.3 发布前**的历史审查快照。原文曾建议先保留已交付的旧 APK，
> 此建议不是当前发布状态，也不意味着后来完成了实机验收。

**范围：**对 V1.0 公开源码快照 `3e503d1` 的原生 ASR 任务状态、Android 生命周期、
对话／云端／隐私、Shizuku 网络规则副作用、导出／数据留存、构建输入和二进制许可进行审查。
三个并行的只读审查分支克隆了公开提交，发现与本地源码核对后才修改；
随后另一名补丁审查者发现缓存结果重放、清理缓存确认竞态和过严的历史大小上限，
这些问题在发布前已处理。这是**源码审查**，不是设备渗透测试、法律意见或
HyperOS 已显示岛的证据。

## 主要发现及处理

| 源码层面的发现（未做设备攻击验证） | 当前源码中的修正 |
| :--- | :--- |
| 任务运行中导入可能截断共用的 `cache/input`；Activity 重建可能让运行任务看似空闲。 | 每次导入使用独立临时文件；运行中拒绝替换；跟踪并发导入；重建后恢复活动任务信息／进度，防止忙碌服务重置通知。 |
| 结果只由 Activity 保存，页面停止时可能丢失或重复保存。 | 服务先持久化再发布 Bus 事件；界面从记录 ID 读取并忽略重复事件；历史使用唯一 ID、有界读取和 Android `AtomicFile` 写入。 |
| 文件选择器返回后，全文／首页的导出正文可能因重建丢失，得到空文档。 | 跨重建只保存格式与记录 ID，回来从历史重新生成正文；状态／输出流缺失时显式失败；云识别标签可辨；零长度 SRT 字幕增加正时长。 |
| 请求处理中清空对话后，迟到回复又写回已清空的记录。 | 清理或 Activity 销毁后以 generation token 拒绝过期回调。 |
| 按子串判断 HTTP 例外可能把路径误认为本地回环地址；重定向规则不明确。 | 核验真实 URL scheme／host；带 bearer key 时禁用重定向；响应体读取上限 2 MiB。 |
| 为 XMSF 启用原本关闭的全局 OEM 防火墙链可能影响其他应用。 | 新任务不再启用共享链；若链原本关闭，岛尝试回退普通通知；新任务的恢复流程不改写链状态，旧待恢复记录仍走兼容处理。 |
| 原始失败报告曾自动发布到公共 Download；试听音频留在缓存。 | 报告及布局诊断仅存在私有目录，可在设置中按需查看；试听缓存私有，非运行时可主动清理。 |
| 并发模型准备共用 `.partial` 文件，`ready()` 只检查非空。 | 准备串行化，按 APK 内各模型的预期字节长度检查就绪状态。 |
| Maven 缓存只要非空就信任、未核对 AAR 解出的 JAR；二进制许可仅有链接。 | 锁定并复核 7 项 Maven 制品 SHA-256，对照 AAR 校验 JAR，并在本地 APK 中附完整 MIT、Shizuku MIT 与 Apache-2.0 文本。 |

## 当时实际运行的检查

- `bash design-tools/check-all.sh`：逻辑、UI/XML 不变量、云／岛保护、导出与岛载荷案例。
- `bash scripts/prepare-libraries.sh`：缓存 Maven 哈希与 Maven Central 原始字节一致；AAR 中的 classes 与提取产物一致。
- `bash build.sh`：本机 APK 构建、签名、ZIP／DEX／模型打包及三份许可文本校验。
- 发布源码前运行 `git diff --check` 和跟踪文件／许可边界检查。

这些检查**不证明**实机行为。安装新构建前仍应在手机上测试导入 → 旋转 → 继续／取消、
导出 → 旋转 → 保存、慢响应时清理对话、普通通知回退、键盘／输入法和真正的岛显示。
同版本号的本地构建不等于公开 Release。**历史说明：**此审查提出在设备验收前保留旧 APK；
后来 v1.0.3 已公开发布，但上述设备验收并未因此自动完成。

## 尚存限制／未知项

- 单条历史读取上限 128 MiB；更大的旧 JSON 记录需要流式读取器／迁移器，不能无限分配内存。
- JNI 识别和整段分人可能占用大量内存且无法立即取消；取消在可用阶段边界传播，
  阻塞原生调用内无法保证中断。改为流式或有界分人仍须实机测试。
- OEM 共享链初始关闭时，实验性 Shizuku 岛会回退普通通知，可能比旧版少显示岛。
  这是明确的安全取舍：不能为了一个岛效果激活影响其他应用的全局规则。
- Maven 依赖有字节级哈希；人工提供的 SDK、sherpa AAR 与模型**不受该清单来源核验**，
  应自行检查来源和哈希。干净克隆在缺少另行取得的授权资产时无法完整构建。
- 流式 Zipformer 再分发权与 `embed.onnx` 的确切来源尚不明确；不要将它们作为 MIT 模型包发布。
- 静态检查与本机构建不能证明实机可访问性、全部音频编码、OEM 防火墙状态或 SystemUI 岛展示。
