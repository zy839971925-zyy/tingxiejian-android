# Source review — 2026-09-28

> [!NOTE]
> Historical snapshot of the pre-v1.0.3 release review. The old instruction below to keep a
> previously delivered APK unchanged was written **before** v1.0.3 was built and published;
> it is not a current release status or a claim of later device acceptance.


**Scope:** V1.0 public source snapshot `3e503d1`, reviewed across native ASR job state,
Android lifecycle, chat/cloud/privacy, Shizuku network-rule side effects, export/data retention,
build inputs and binary licensing. Three parallel read-only review branches cloned the public commit;
findings were checked against the local source before changes. A separate patch reviewer then
found a cached-result replay, a cache-clear confirmation race and an overly strict history cap;
these were addressed before publication. This is a source review, **not** a device penetration
test, a legal opinion or proof that HyperOS renders the island.

## Material findings and disposition

| Finding (source-backed; not device-exploited) | Corrective action in current source |
| --- | --- |
| Importing while a job runs could truncate the shared `cache/input`; Activity recreation could make the running job look idle. | Each import now uses a distinct temporary file, refuses replacement while a service job runs, tracks overlapping imports, restores active metadata/progress after recreation and prevents a busy service from resetting its notice. |
| Results were only saved by the Activity; if it was stopped when the service completed, a result could be lost or a cached result saved twice. | The service now saves the result *before* posting its Bus event; UI loads the persisted ID and ignores repeat delivery. History uses unique IDs, bounded reads and Android `AtomicFile` writes. |
| File-picker recreation could clear the pending export body in both transcript and home pages and produce an empty document. | Only format/record ID is saved across recreation; body is regenerated on return, missing state/output streams fail visibly. Export labels identify cloud recognition, and zero-length SRT cues have positive duration. |
| Clearing chat while a reply was in flight allowed the reply to repopulate a deleted conversation. | Pending callbacks are rejected after clear or Activity destruction using a generation token. |
| A substring-based HTTP exception could mistake a path for a loopback host; redirect handling was unspecified. | Actual URL scheme/host is validated, redirects are disabled when a bearer key is attached, and response reads have a 2 MB bound. |
| Enabling an inactive global OEM firewall chain for XMSF could activate rules for other applications. | Never enable the chain in a new run; when it is disabled the optional island path declines and normal notifications continue. Restore no longer overwrites the chain state for new runs. Older pending recovery entries still use the legacy restore path. |
| Raw failure reports were automatically published to shared Downloads; temporary imported audio remained in cache for playback. | Reports and layout diagnostics are private and viewable on demand in Settings. Audio remains private for preview; Settings offers an explicit cache-clear control when no job is active. |
| Concurrent model preparation used shared `.partial` files; `ready()` only checked nonzero length. | Preparation is serialized and readiness checks match each embedded model's expected byte length. |
| Maven artifacts and extracted compile JARs were trusted when merely nonempty; binary licenses were only linked. | Pin and recheck SHA-256 for seven Maven artifacts, compare extracted JARs with their AARs, and include full original MIT, Shizuku MIT and Apache-2.0 license texts in locally built APKs. |

## Checks actually performed

- `bash design-tools/check-all.sh`: logic checks, UI/XML invariants, cloud/island guards, export checks and payload cases.
- `bash scripts/prepare-libraries.sh`: cached Maven digests match direct Maven Central bytes; extracted AAR classes match the original AARs.
- `bash build.sh`: local APK compiles, signs, verifies ZIP/DEX/model packaging and includes all three license texts.
- `git diff --check` and tracked-file/license boundary checks before publishing source.

These checks **do not** prove device behavior. Before installing the changed build, repeat the
on-device import → rotate → continue/cancel, export → rotate → save, chat clear during a slow
reply, notification fallback, keyboard/IME, and actual island display checks. A local build with
the same version code is not a public APK release. At review time the recommendation was to keep
previously delivered APKs unchanged until a new build passed device acceptance. **Historical note:**
v1.0.3 was subsequently published; the listed device checks were not thereby completed.

## Remaining constraints / unknowns

- History entries are bounded at 128 MiB; still-larger legacy JSON files require a streaming
  reader/migration to open safely rather than an unbounded allocation.
- Native JNI recognition/whole-file diarization can hold substantial memory and cannot always be
  cancelled promptly; cancellation is propagated at available phase boundaries, not inside a
  blocking native call. A streaming or segment-bounded diarization redesign needs device testing.
- If the OEM chain starts disabled, the experimental Shizuku island path may now fall back where
  the previous build worked. This is an explicit safety trade-off: do not activate global rules
  for unrelated apps merely to preserve an island animation.
- Maven dependencies are byte-pinned. Manually supplied Android SDK, sherpa AAR and models are
  **not** provenance-verified by that manifest; confirm source and hashes independently. A clean
  checkout cannot build without separately licensed assets.
- Streaming Zipformer redistribution rights and the exact origin of `embed.onnx` remain unclear.
  Do not publish model weights or an APK bundling them as an MIT release.
- Static checks and a successful local build cannot establish real-device accessibility, all
  audio codecs, OEM firewall state or SystemUI island presentation.
